# DNF Market, 던파 시세 분석·브리핑

던전앤파이터 경매장 시세를 매일 자동으로 모으고, 크게 움직인 품목이 왜 움직였는지까지
사람 손 없이 적어 내보내는 대시보드입니다.

**대시보드**: https://dnf-market.vercel.app

사이트 이름은 DNF Market입니다. 저장소는 https://github.com/Yegeon99/dnf-market, 배포 주소는 https://dnf-market.vercel.app 입니다.

형제 프로젝트는 [DNF Census](https://dnf-census.vercel.app)입니다. 시장 대신 유저를 보는
캐릭터 표본조사 리포트이고, 두 프로젝트는 같은 디자인 언어를 씁니다.

![마켓 오버뷰 화면](docs/screenshots/overview.png)

> 지금 얼마인지 보여주는 조회 도구가 아닙니다. 왜 움직였고 무엇을 눈여겨봐야 하는지를
> 매일 한 편의 글로 만들어 내보내는 것이 목적입니다.

## 무엇을 만들었나

던파 경매장 품목 31종의 값을 하루 최대 여섯 번 모읍니다. 어제와 견줘 크게 움직인 품목이
있으면 규칙으로 먼저 걸러내고, 걸린 항목만 AI에게 넘겨 공식 공지와 대조해 원인 가설을
쓰게 합니다.

그날의 이야기는 매일 심야에 짧은 브리핑으로 발행됩니다. 수집부터 발행, 배포까지 사람이
누르는 버튼은 없습니다. 이 저장소의 커밋 기록이 그 증거입니다.

이상이 하나도 없는 날은 AI를 부르지 않고 규칙만으로 "조용한 날"이라고 적습니다. 없는
이슈를 만들지 않기 위해서입니다.

## 어떻게 돌아가나

Neople 오픈 API는 지나간 시세를 돌려주지 않습니다. 그래서 값을 볼 때마다 직접 찍어
쌓는 구조를 만들었습니다. 수집을 시작한 날이 곧 이 데이터의 시작입니다.

```
Neople 오픈 API (경매장 등록가 · 판매 완료)
        ↓  GitHub Actions 예약 실행, 하루 최대 6회
           KST 02:17 · 07:17 · 11:17 · 15:17 · 19:17 · 23:17
collect.py    시세를 찍어 저장 (31품목, 회차당 62호출, 집계 수치만 남김)
        ↓
aggregate.py  회차들을 시계열 하나로 합침 (같은 회차가 두 번 들어와도 한 번만 반영)
        ↓  심야 회차에서만 이어서 실행
detect.py     규칙으로 이상 변동 판정
        ↓  걸린 항목만
interpret.py  앞뒤 3일 공지·이벤트와 대조해 원인 가설 작성 (근거 주소와 신뢰도 병기)
        ↓
briefing.py   그날의 브리핑 발행
        ↓  봇이 data/ 경로만 커밋
   git push   Vercel이 자동으로 다시 배포하고 화면이 갱신됨
```

수집 시작일은 2026년 8월 25일입니다. 그 이전 구간은 판매완료 기록을 거슬러 올라가
2026년 7월 26일부터 8월 24일까지 30일치 실거래만 하루 단위로 채워 넣었습니다.
등록가와 매물 수는 지난 값을 조회할 방법이 없어 채우지 않았고, 화면에서 이 구간은
점선으로 구분해 표시합니다.

## 운영하며 겪은 일

만들 때 정한 규칙보다, 돌리면서 부딪힌 일이 이 프로젝트의 내용에 더 가깝습니다.

### 점검일에 하루치가 통째로 비었습니다

2026년 8월 27일 새벽 회차에서 62번의 호출이 전부 실패했습니다. 게임 정기점검과 겹쳐
API가 통째로 닫혀 있었습니다. 값이 하나도 없는 회차를 시계열에 넣으면 그날 시세가
0으로 꺾인 것처럼 보이기 때문에, 실패한 회차는 합치지 않고 차트에 빈칸으로 남기기로
했습니다. 대신 그 사실을 화면 상태 바에 그대로 띄우고, 수집이 실패한 날에도 전날 값을
기준으로 브리핑을 내보내게 했습니다. 지금은 전 품목 실패라도 원인이 외부 장애면 경고만
남기고 정상 종료하고, 인증이나 코드 문제일 때만 실패로 처리합니다.

### 계산 방식을 바꾸자 과거 브리핑이 재현되지 않았습니다

대표 가격을 매물 평균으로 잡았더니, 매물이 두 건뿐인 품목에서 시세의 열 배로 올려둔
한 건이 평균을 통째로 끌고 갔습니다. 그래서 중앙값으로 바꾸고 회차 라벨도 수집 시각
기준으로 다시 매겼습니다. 그러자 이전에 발행한 브리핑 세 건의 수치를 지금 데이터로는
다시 만들어 낼 수 없게 됐습니다. 발행된 글을 나중에 손보면 아카이브가 기록이 아니게
되므로 과거 브리핑은 고치지 않았습니다. 대신 해당 브리핑에 발행 당시 기준이라는 안내를
붙이고, 자동 검증은 계산 방식이 바뀐 날을 기준으로 구간을 나눠 이전 구간의 재현 불가
건수를 목록으로 보여 줍니다.

### 예약 실행이 조용히 밀렸습니다

정각에 예약을 걸어 두었더니 실행이 늦어지거나 아예 건너뛰는 회차가 생겼습니다. 예약이
30분에서 110분까지 밀리는 날도 있었고, 그 바람에 새벽 3시로 걸어 둔 회차가 목요일
점검 시간과 겹쳐 통째로 실패했습니다. 지금은 모든 회차를 정각이 아닌 17분으로 옮기고,
심야 회차를 2시대로 앞당겨 점검 시간을 피합니다. 그래도 회차는 빌 수 있어서, 화면에는
예약 횟수가 아니라 실제로 성공한 회차 수를 적습니다.

## 무엇을 어떻게 탐지하나

두 가지만 봅니다. 어제와 견준 변화, 그리고 최근 7일 평균에서 얼마나 벗어났는지입니다.
기준값은 [config/thresholds.json](config/thresholds.json)에 전부 적어 두었고 화면에도
그대로 공개합니다.

| 규칙 | 지표 | 낮음 | 중간 | 높음 |
|---|---|---|---|---|
| 어제와 견주기 | 등록 대표가 | ±8% | ±15% | ±30% |
| 어제와 견주기 | 매물 수 | ±30% | ±50% | ±100% |
| 7일 평균에서 벗어남 | 등록 대표가 | 없음 | ±12% | ±25% |
| 7일 평균에서 벗어남 | 매물 수 | 없음 | ±40% | ±80% |

7일 평균 규칙은 그 품목의 값이 7일 넘게 쌓인 뒤부터 자동으로 켜집니다. 그 전에는 어제와
견주기만 씁니다. 어제와 견줄 때는 두 날에 모두 있는 회차끼리만 비교합니다. 회차 구성이
다른 날을 그대로 견주면 시간대 차이가 변동률로 둔갑하기 때문입니다.

매물이 30건보다 적은 품목은 등록 한두 건으로 지표가 크게 흔들립니다. 이런 품목은 같은
방향 변동이 그날 두 회차 넘게 이어질 때만 중간 이상으로 보고, 화면에 저유동 표시를 붙여
해석에 주의하도록 안내합니다. 매물이 5건 미만인 날이 이틀 이어지면 가격 신호 자체를
쓰지 않습니다.

AI가 쓰는 가설에는 규칙이 있습니다. 손으로 골라 둔 공식 공지 가운데 앞뒤 3일 안의 것만
근거로 쓰고, 근거 주소와 확정인지 추정인지를 반드시 함께 적습니다. 근거가 없으면 원인
미상으로 남깁니다. 시점이 겹친다는 이유만으로 원인이라고 단정하지 않습니다.

## 품목 31종을 고른 기준

전 품목을 훑지 않고 시장을 대표할 만한 품목만 골랐습니다. 후보 64종을 검색해 경매장에
실제로 매물이 있는 31종만 남겼습니다. 매물이 0건인 33종은 귀속이거나 거래가 막힌
품목으로 보고 제외했습니다.

| 묶음 | 종수 | 왜 넣었나 |
|---|---|---|
| 큐브 조각 | 4 | 전 직업이 쓰는 기초 재료라 경제의 기준점이 됩니다 |
| 제작·마법부여 재료 | 3 | 장비를 만들고 옵션을 붙일 때 계속 소모됩니다 |
| 증폭 재료 | 2 | 고점 수요라 이벤트에 민감합니다 |
| 기타 재료 | 3 | 시즌 콘텐츠 수급과 바로 이어집니다 |
| 확률형 상자 | 1 | 상자 이벤트가 열리면 값이 즉시 반응합니다 |
| 마법부여 | 4 | 값이 비싸고 매물이 적어 패치 영향이 큽니다 |
| 레어 클론 아바타 | 12 | 아바타 상자 이벤트에 가장 빠르게 반응합니다 |
| 일반 클론 아바타 | 2 | 레어와 견주기 위한 대조군입니다 |

품목마다 고른 이유를 [config/items.json](config/items.json)에 한 줄씩 적어 두었고
화면의 방법론 페이지에도 그대로 싣습니다.

이름이 완전히 같은데 거래소에서는 다른 아이템으로 취급되는 클론 아바타가 있습니다.
공개 API가 주는 이름, 등급, 분류, 설명, 세트가 모두 같아 무엇이 다른지 알 방법이 없어
등록 순서로 번호만 붙였습니다. 게임에 없는 표현은 지어내지 않았습니다.

## 비용 실측

AI는 이상으로 걸린 항목에만 부릅니다. 전 품목을 넣고 돌리는 일은 하지 않습니다.

| 단계 | 모델 | 회당 실측 | 누적 |
|---|---|---|---|
| 원인 해석 | claude-haiku-4-5 | $0.0016 | 32회 $0.05 |
| 브리핑 발행 | claude-opus-5 | $0.0380 | 14회 $0.53 |

하루 비용이 가장 컸던 날은 2026년 8월 30일의 $0.29입니다. 그날은 브리핑을 여러 번 다시
돌린 날입니다. 평상시 하루는 브리핑 한 번에 해석 몇 건이라 훨씬 적습니다.

하루 상한을 $0.30으로 두고 넘으면 실행을 멈춥니다. 브리핑마다 든 비용은 화면에 그대로
표시합니다.

## 데이터 윤리 원칙

- API가 돌려준 응답 원본은 저장하지 않습니다. 분석에 필요한 집계 수치만 남깁니다.
- 요청 예절을 지킵니다. 호출 사이 0.3초를 쉬고 재시도는 두 번까지만 하며, 서버가 통째로
  닫힌 구간에서는 남은 재시도를 끊습니다. 하루 수집은 최대 여섯 회차, 372호출입니다.
- 수집이 실패한 회차를 채워 넣지 않습니다. 차트에 빈칸으로 그대로 둡니다.
- 값을 다시 계산하는 방식이 바뀌면 과거 발행분을 고치지 않고 안내를 붙입니다.
- 매물 수는 조회 상한 400건, 실거래는 최근 100건 안에서 집계한 값입니다. 이 한계를
  화면에 함께 적습니다.
- 모델 비용을 실측으로 공개합니다.
- 게임 그래픽은 Neople 오픈 API가 주는 아이템 아이콘만 씁니다.

## 어떻게 만들었나

```
pipeline/              # Python 파이프라인
  collect.py           # 시세 수집 (0.3초 대기, 재시도 2회, 외부 장애 판정)
  aggregate.py         # 회차 병합, 실패 회차 제외
  detect.py            # 규칙 기반 이상 판정
  interpret.py         # 공지 대조 원인 가설 (이상 항목만)
  briefing.py          # 그날의 브리핑 발행
  llm.py               # 호출 비용 원장, 하루 상한
config/                # 품목과 선정 사유, 임계치, 공지·이벤트 목록
data/                  # 회차별 기록, 시계열, 이상, 브리핑, 비용 원장
dashboard/             # Vite + React 4화면 대시보드
.github/workflows/     # 예약 수집과 심야 분석
docs/                  # 검수 기록과 진행 체크리스트
```

### 재현

```bash
# .env에 NEOPLE_API_KEY (브리핑까지 돌리려면 ANTHROPIC_API_KEY 추가)
python -m venv .venv && .venv/Scripts/pip install -r requirements.txt

.venv/Scripts/python pipeline/run_daily.py    # 수집, 병합, 판정, 해석, 발행을 순서대로

cd dashboard && npm install
npm run dev                                   # 시작 전에 data/를 화면용으로 복사합니다
npm run audit                                 # 화면 수치와 저장값, 재계산값 3중 대조
node scripts/screenshot.mjs                   # 1440·390 화면 촬영과 자동 점검
node scripts/verify-live.mjs                  # 배포본 전 화면 훑기
```

`npm run audit`은 화면이 쓰는 계산, 파이프라인이 남긴 값, 원본에서 다시 계산한 값을
서로 대조합니다. 브리핑 본문에 적힌 백분율이 실제 데이터에 있는 수치인지까지 확인합니다.

## 이 대시보드에서 쓰는 말

화면 문구는 쉬운 말로 씁니다. 줄표를 쓰지 않고, 코드 이름과 내부 지표 이름을 화면에
노출하지 않습니다. 수집에 실패했으면 실패했다고 적고, 값이 없으면 없다고 적습니다.

## 고지

본 서비스는 Neople 오픈 API에서 제공받은 데이터를 일부 가공하여 활용하고 있습니다.
비공식 팬메이드 포트폴리오이며 ㈜네오플, 넥슨과 무관합니다. 게임 그래픽은 Neople 오픈
API가 제공하는 아이템 아이콘만 사용합니다.
